## Background
After the development process of the [BLUE Android Design System](/projects/blue-android-design-system) was completed, the next phase focused on continuous *maintenance*, feature development, and bug fixing. At the same time, there was an internal KPI to measure the adoption rate of the BLUE Android Design System across all Android projects.

During the implementation process, challenges were still found regarding the understanding and adoption of components. Designers and Android developers needed a clearer reference on how components are used in real contexts, both from interaction and implementation perspectives, so that design discussions and decision-making processes could run more efficiently.

Without a structured exploration medium, the communication process between designers and developers often took longer due to the lack of visual and technical guidelines that could be used as a shared reference. To answer these needs, a solution in the form of an **interactive catalog** was needed to bridge the two roles in understanding the BLUE Android Design System more practically and consistently.

## Problem Identification
Based on these conditions, there were several main problems in the adoption process of the BLUE Android Design System, including:

* The adoption rate of the design system was not yet optimal, thus not fully achieving the established internal KPIs.
* Developers needed more concrete and accessible component implementation references without having to refer to documentation scattered across various sources or manual exploration processes.
* Designers needed a faster way to understand the interaction and behavior of components directly in a more representative and easily explorable format.
* The lack of a centralized medium that could be used as a shared reference to explore components, interactions, and implementations of the design system consistently.

## Goals & Objectives

The main goal of this project was to develop the <strong className="text-primary font-semibold">BLUE Android Catalog</strong> as an interactive exploration medium to increase the adoption of the BLUE Android Design System and strengthen mutual understanding between designers and developers.

To achieve this goal, several main objectives were established as follows:

* Increase the adoption rate of the BLUE Android Design System according to the established internal KPIs.
* Provide easier access to UI element implementation references that resemble *real usage* to help developers understand component usage faster and more accurately.
* Deliver an interactive exploration medium for designers and developers to understand component behavior, *states*, and interactions directly without relying on static documentation.

## Roles & Responsibilities

In this project, I acted as a UX Engineer and PIC (Person in Charge) responsible for developing the BLUE Android Catalog as a design system exploration medium.

The responsibilities undertaken included:

* Developing the BLUE Android Catalog as an interactive exploration application to understand the behavior, *states*, and interactions of components in the BLUE Android Design System.
* Implementing UI appearances and interactions to represent component behavior according to design system standards.
* Acting as the PIC in the project, including coordinating requirements, development direction, and synchronization with designers.
* Collaborating with designers and Android developers to ensure alignment between design, behavior, and technical implementation.
* Structuring the catalog so that components, documentation, and usage examples can be easily explored by designers and developers.
* Ensuring implementation quality through code reviews, QA, and iteration based on team feedback.

The development and execution processes carried out included:

* Conducting discussions with designers to discuss the application's design, information architecture, and user flow.

## Results
This project successfully delivered the <strong className="text-primary font-semibold">BLUE Android Catalog</strong>, an interactive catalog application for the BLUE Android Design System that can be used by designers and Android developers as a reference medium for component implementation and UI interactions more easily and in a structured manner.

This application provides several main pages and features, including:
* Home page as the main access to explore the BLUE Android Catalog.
* Component list page to display the entire list of components in the BLUE Android Design System.
* Component detail page displaying usage examples and complex interaction *cases* on UI elements.
* Changelog page to display information on application updates and development.
* Support page (FAQ) to help users understand the application and component usage.
* Component icon page to display the list of icon libraries available in the BLUE Android Design System.
* Component search feature to simplify the component search process within the application.

In addition to the BLUE Android Catalog application itself, this project also included the APK distribution medium so the application can be easily accessed and downloaded by users internally via the [BLUE Documentation - App Catalog Page](https://blue.blibli.com/blue3/resources/app-catalog).
